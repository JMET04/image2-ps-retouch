# 原片精修

Image2 提供审美方向；Photoshop 处理原片。不得用生成图片替换原片、放大参考图冒充原尺寸成片，或把失焦/信息丢失当成能恢复的细节。

## 工作流程

先做小样环境检查：确认 Photoshop 已进入编辑界面，能打开一张已授权原片，并在新的输出路径实际保存可编辑 PSD 和 JPEG。原生保存与视觉检查通过后再扩展到大量参考图与批量执行。`GetActiveObject` 只能连接已运行的 Photoshop；连接失败、静态语法检查和生成配方均不代表原生引擎已验证。

启动失败时，依据实际显示的错误排查。暂存盘已满可在 Photoshop 暂存盘设置中选择空间充足的盘，先记录原选择；参考 [Adobe 暂存盘错误说明](https://helpx.adobe.com/photoshop/desktop/troubleshoot/performance-stability-issues/troubleshoot-scratch-disk-full-errors-in-photoshop.html)。不要为腾出空间删除用户资料。记录未解决的环境问题，先完成有限的素材准备，环境恢复后继续同一批次。

原生调用必须通过 `scripts/photoshop_job.py` 的 `native_guard.py` 执行；不要另写无截止时间的 COM 调用。默认每次 240 秒、跨进程串行、输出盘预留 16GiB；超时仅结束 Python 客户端，PS 结果仍不确定，持久状态会拒绝下一任务。先实际检查 PS 与输出，确认作业结束且无用户文档，再运行 `--recover-native` 的限时零文档探针。禁止删除锁状态、并发重试或杀 PS 绕过。暂存空间紧张时每批至多三张，批次结束且零文档后用 `--quit-idle` 正常退出，确认进程退出/空间释放，再正常启动已核实版本；不得关闭用户文档。模型容量错误是服务层问题，不能以杀 PS 或削减用户数量要求处理。

下载超时时可重试当前授权任务并记录状态；`.downloading` 文件可能已预分配全尺寸，不能凭文件长度判断完整。仅对正式文件名、下载完成且能正常解码的原片做焦点复核。网盘提示网络异常不能直接证明防火墙是原因，不据此更改网络或安全设置。

只有空间受限且已有单张峰值实测时，才可采用配方文档中受约束的 `--fresh-small-session` 例外：唯一已核实新进程60秒内、源绑定尺寸<=20.1MP、<=12步、9GiB余量、每进程一张并正常退出。PID领取与未知结果阻塞不能绕过。这不是通用16GiB规则的替代，也不满足Adobe100GB建议。完整条件与包装脚本见 [配方与执行](references/recipe.md)。

1. 确认照片来源、用户指定目录、数量与输出位置。已有授权直接执行，未指定风格时按照片自身光线选择自然、有层次的摄影处理。保留源文件。
2. 用户要求屏幕选片时，使用现有 Computer Use 能力读取缩略图并操作下载；只进入指定来源。观察到页面正在加载时刷新后再选择。下载入围照片，数量可略多于最终需要。无需浏览全库。
3. 缩略图判断主体、构图、光线、边缘干扰、表情/姿态与组图多样性。同场连拍只选更好的瞬间。轻度欠曝、能小幅裁切改善、或能通过局部光影突出主体的照片可以入围。
4. 原图复核曝光与焦点。技术指标只提示风险，不决定美学选片；白雪/反光/黑色衣物不能仅因直方图端点而淘汰。100% 查看主体焦点，必要时查看可恢复高光、噪声、压缩和运动模糊。淘汰不可恢复的关键主体曝光丢失、真正失焦、无主体且裁切不能解决的构图。
5. 为入选照片用内置 image_gen 生成参考图；先用 view_image 检查本地输入。按 [参考图要求](references/art-direction.md) 写逐张提示词并保存提示词和参考结果。不要擅用其他模型或 CLI 替代 image2。参考照片不得成为成片的像素来源。
6. 按 [逐区域参考匹配与迭代](references/reference-matching.md) 比较原图与真实新参考，写差异表与逐张配方。锁住原画框，禁止扩边；有限裁切/水平校正须记录同一几何对应关系。分别检查全局明暗、主体/环境对比、受光/背光体积、肤色/白雪/天空/湖水及边缘。被重画的身份、结构与纹理不复现；明显扩边或不可实现的主要变化须重生成，不能降级到旧参考凑数。
7. 由 ChatGPT 视觉模型查看 Photoshop 解码的原片基线和原像素局部，标注面部、手部、主体轮廓、天空和光影区域。按 [模型标注与蒙版](references/vision-annotations.md) 保存坐标、观察图、边缘不确定性及标注预览复核。禁用 Photoshop 的自动主体、天空和物体识别，不调用它们来代替模型标注。坐标映射工具只计算几何，不能冒充识别模型。
8. 需要局部塑光时读 [局部光影塑造](references/local-lighting.md)；主动改变视觉重心和体积时再读 [光影设计与关层复核](references/light-design.md)。由模型判断主光方向和视觉主次，分别设计补光、压光与体积过渡，不以整体调色代替。使用独立 `local_light` 图层，强度与羽化按原图判断，不能把阴影全部提平。随后在 Photoshop 执行逐张配方，检查蒙版边缘、主体与原图细节。可用插件根目录 scripts/photoshop_job.py 调用已运行 Photoshop 的 ExtendScript 引擎。运行前读 [配方与执行](references/recipe.md)。不要批量复制单一预设宣称逐张精修。
9. 如实际应水平的远岸倾斜，按配方文档增加模型复核细带，几何模块只换算该标记角度；禁止自动找地平线。内嵌未校正像素，所有图层与蒙版一起旋转一次后有限裁切，不填角、不放大；检查旋转插值对焦点的影响。不要把透视斜岸或山坡误当水平线。
   逐张检查脏点、临时皮肤瑕疵和局部色差，需要修复或从已验收PSD继续时读 [局部修复与续修](references/repair-and-revision.md)。小克隆必须由模型确认目标和取样，保留毛孔、痣及个人特征；新增加光优先连续受光面与体积转折，不能统一磨皮或全脸提亮。
10. 每轮实际从PS导出工作样，再与参考并看；找到最大剩余差异，继续修改对应局部曲线和蒙版，直到主要观感基本相同。`scripts/reference_match.py` 只在模型实际复核对应关系后拟合曲线参数、计算对应区域Lab/ΔE00辅助差异，不能生成成片或自动接受。即使某几个区域指标通过，整图仍有明显偏黄白雪/偏绿公路/主体过暗，也必须迭代。轮数、图层数量和成功执行都不是完成依据。
11. 最终保存16位可编辑PSD与高质量sRGB JPEG，实际检查整体光影、100%主体纹理、天空/山脊/人物边缘和与新参考的相似程度。内部工作样可仅保留JPEG/配方/执行记录，最终必须实际有PSD。标注预览通过不代表最终蒙版通过；仅真正完成视觉匹配与质量验收的不同原片计入数量。自动统计不能证明“大师水平”；用 [验收标准](references/art-direction.md) 和参考匹配指南记录实际判断。

## 记录

每张照片记录源路径、入选理由、技术风险、主体区域、参考图路径与提示词、可复现调整、不可复现差异、配方、PSD/JPEG 路径及人工视觉验收结果。建立批次清单，未处理、失败与待复核不得计为完成。

脚本只读取已下载、已授权的文件；不读取网盘内部缓存、账号资料、全库数据库或其他目录来代替屏幕选片。
